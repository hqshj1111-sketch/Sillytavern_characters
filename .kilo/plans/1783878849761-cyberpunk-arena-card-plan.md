## 二、阶段流程 (9阶段)

```
创角阶段 → 幕间日常 → 赛前准备 → 性斗入场 → 性斗阶段 ──┬── 胜利享用(主角耗尽对手精力)
                                                          ├── 败北惩罚(对手耗尽主角精力)
                                                          └── 平局收场(回合上限无胜负)
                                                               ↓
                                                          擂台结算 → 幕间日常(循环)
```

| 阶段 | 核心活动 |
|------|----------|
| 创角阶段 | HTML表单创建角色 |

## 三、战斗系统

### 3.1 战斗属性 (无上限)

| 属性 | 初始值 | 说明 |
|------|--------|------|
| **性技** | 50 | 进攻值，训练/改造提升，无上限 |
| **忍耐度** | 50 | 防守值，抵抗快感冲击，无上限 |
| **最大体力值** | 100 | 战斗中每回合攻击消耗体力，体力归零触发惩罚骰 |
| **最大精力值** | 100 | 胜负HP，仅通过射精减少，归零即败北 |
| **快感阈值** | 100 | **固定值**(射精后不增加)，通过平时训练提升。快感值超过后触发射精 |

### 3.2 对战流程

1. 双方轮流进攻，监控器自动交替当前进攻方
2. 骰子: 进攻方 `floor(性技/10)`×D20 vs 防守方 `floor(忍耐度/10)`×D20
3. **仅进攻方消耗体力**(从当前体力扣除)，防守方承受快感/射精
4. 体力≤0 → 进攻方骰子数-1(最低1)，体力不再扣除
5. 快感值 > 快感阈值 → **射精** → 当前精力减少 → 快感值清零 → 快感阈值不变
6. 回合上限20 → 平手

### 3.3 5档动态数值

数值 = 基础值 ± floor(性技差/10)，性技差 = 进攻方性技 - 防守方忍耐度

| 档位 | 攻体力消耗 | 守快感增长 | 射精触发 | 射精精力消耗 |
|------|-----------|-----------|----------|-------------|
| 大成功 | 5-15 | — | 必定 | 30+差/10 |
| 成功 | 10-25 | — | 必定 | 20+差/10 |
| 纠缠 | 10-25 | 大量 | 超阈触发 | 15+差/10 |
| 失败 | 15-30 | 一定 | 超阈触发 | 10+差/10 |
| 大失败 | 20-40 | 微弱 | 极罕见 | 5+差/10 |

### 通用EJS骨架

所有 `.txt` 条目遵循:
```
<%_{
const stat = getvar('stat_data');
if (condition) {
%>
[渲染给AI的正文，含 <%= 插值 %> 和 <%- j(val) %>]
<%_ }} _%>
```

- `getvar('stat_data')` — 获取完整变量树
- `_.get(obj, 'path', def)` — 安全嵌套读取
- `<%= val %>` — 直接插值
- `<%- j(val) %>` — JSON字符串化插值 (用于Patch块)
- `_.random(min, max)` — 骰子随机数

### JSONPatch操作 (来自最终输出协议)

AI在 `<UpdateVariable><JSONPatch>[...]</JSONPatch></UpdateVariable>` 中仅使用:
- `replace` — 替换已存在路径的值
- `delta` — 数值路径加减
- `insert` — 数组追加(`/path/-`)或对象插键(`/path/Key`)
- `remove` — 删除键或元素

### 正文结构规范 (EJS渲染后的提示词部分)

以下为三张参考卡(LittleHero/NudeLiveStreaming/Isekai_Dungeon)词条中**渲染后AI实际读到的正文**的结构规律总结。

#### 头部标识

两种固定头部，直接作为第一行：

| 头部 | 使用场景 |
|------|----------|
| `# 指令: XXXX` | 事件类条目 (如 `# 指令: 战斗胜利！` `# 指令: 蜕变`) |
| `# 系统指令: XXXX` | 系统类条目 (如 `# 系统指令: 露出直播 - 日常阶段` `# 系统指令: 战斗系统`) |

复杂多分支词条(如"战斗结束"同时处理终结回合/胜利/败北)用 `---` 分隔不同分支段落。

#### 段落组织: YAML式键值块

正文使用**首层键名+缩进**组织，类似YAML风格但不是严格YAML——它是键值对堆叠的Markdown文本：

```
event_handler:                    ← 主入口声明块名
  event_name: "XXX"               ← 事件标识
  context: "..."                  ← 情境叙述 (AI读作背景铺垫)
  narrative_guidance:             ← 叙事指令 (必有，核心)
    - "引号包裹的具体指令"        ← 指令条目，可多行
    - "描写... / 聚焦于..."
  ai_tasks:                       ← 分步任务 (复杂事件)
    - task: "任务名"
      instruction: "任务描述"
  mandatory_data_sync:            ← 变量同步 (有Patch时必有)
    instruction: "操作说明"
    patch_code: |
      [
        {"op":"...", ...}
      ]
  prohibitions:                   ← 禁止项
    - "严禁..."
```

**各块名的作用和适用场景：**

| 块名 | 用途 | 适用 |
|------|------|------|
| `event_handler` | 事件主入口声明 | 所有事件条目 |
| `context` | 当前情境/变量摘要，AI读作叙事背景 | 几乎所有条目 |
| `narrative_guidance` | 叙事指令列表，告诉AI写什么 | **必含** |
| `ai_tasks` / `ai_workflow` | 多步骤任务分拆，每步含task名+instruction | 复杂多段事件 |
| `system_tasks` / `execution_rules` | 系统层面的操作说明 | 含Patch操作的条目 |
| `mandatory_data_sync` / `mandatory_patch` | **必执行的JSONPatch代码块** | 含数值变更的条目 |
| `prohibitions` / `special_restrictions` | 禁止行为清单，语气强硬 | 阶段锁定/战斗系统 |
| `format_strict` | 输出格式约束 (含XML/HTML模板) | 论坛/选项生成 |
| `option_matrix` | 分阶段的行为选项矩阵 | 辅助选项生成 |
| `situations` | 多分支叙事路径 (每分支含condition+narrative_guidance+patch) | 战斗引擎类 |

#### 指令文字的叙述风格

**高频惯用句式:**

| 句式 | 含义 | 使用频率 |
|------|------|----------|
| `描写...` | 要求AI描绘具体画面 | 极高 |
| `聚焦于...` | 指定叙事重点 | 高 |
| `结合[变量]调整...` | 要求根据变量值调整叙事尺度 | 高 |
| `结尾留给主角选择...` | 收束至玩家决策点 | 中 |
| `描绘...的过程` | 要求展开动作细节，不跳步骤 | 中 |
| `不在此回合直接[动作]，为下一回合留出悬念` | 故意分拆情节跨度 | 低(特定场景) |
| `严禁...` / `禁止...` | 硬性禁止，语气不容商量 | 高 |
| `【格式严格】必须使用以下格式` | 输出格式锁定 | 论坛/选项 |

**通用规则:**
- 指令用**完整中文句子**，不缩略、不用编号代替叙述
- 变量插值直接嵌入指令语句 (`他回忆起了<%= oldName %>这个名字`)
- 禁止项总是 `- "严禁...` 开头的独立条目，语气最为强硬
- 分支逻辑的惯用写法: `根据[当前状态]——若[条件]则[描写方向]；若[条件]则[描写方向]`
- 路径映射的惯用写法: `path: "/主角/..."` 后跟 `value: "..."` 样例

#### 三张卡的行文差异

| | LittleHero | NudeLiveStreaming | Isekai_Dungeon |
|---|---|---|---|
| 指令密度 | 高，分拆步骤多 | 中，指令很详细 | 中低，更依赖公式系统 |
| 叙事语气 | 特摄热血感 | 都市现实/内心纠结 | RPG冒险/系统通知感 |
| 状态渲染方式 | EJS插值+布尔分支 | EJS插值+阶段描述性文字 | EJS插值+属性值表格 |
| 选项生成 | 较少使用 | `[第一人称]` 10-20字 | `[第一人称]` 10-20字 |
| 禁止项风格 | `【严禁】...` | `禁止...` | `【视野约束】...` |

#### 对本卡词条正文的建议

1. **头部**: 系统条目用 `# 系统指令: 擂台 - [阶段名]`；事件条目用 `# 指令: [事件名]`
2. **块结构**: 每个事件条目至少包含 `event_handler` → `context` → `narrative_guidance` → `mandatory_data_sync`
3. **叙事指令风格**: "描写..." "聚焦于..." "严禁..." 句式不变，适配灰色调赛博语境
4. **赛前准备/性斗系统**: 参照LittleHero战斗引擎——先渲染双方状态数值表，再给 `narrative_guidance`，最后附 `situations`(多分支)+各分支的 `mandatory_patch`
5. **论坛/选项生成**: 参照NudeLiveStreaming的 `format_strict` + `option_matrix`，选项使用 `[第一人称] 10-20字` 格式
6. **块命名**: 本卡统一使用:
   - `event_handler` (事件) / `system_handler` (系统)
   - `narrative_guidance` (叙事指令)
   - `mandatory_data_sync` (Patch块，统一用此名)
   - `prohibitions` (禁止项)
